# Wording and consistency review — 10 November 2026

Scope: source review of the current Next.js production repository (`meinautoverkauf-next.js/main`), including the valuation form, result page, booking flow, confirmation, admin calendar, PDF labels, email templates, regional pages and API error handling. Findings describe source behavior; this is not an end-to-end browser audit of every deployed page.

Applied change: replace the customer-entered “Wunschpreis” field label with “Preisvorstellung (€)”, validation with “Bitte Preisvorstellung eingeben.”, and the corresponding admin, PDF and email labels with “Preisvorstellung”. Internal API/database field names and pricing behavior remain unchanged. Ordinary editorial references to Wunschpreis in long-form articles are not field labels and were left alone.

All findings below are proposals, not additional fixes.

| Priority | Finding and evidence | Proposed next step |
|---|---|---|
| High | Booking can show success without saving anything: `next-app/components/BookingStep.tsx`, `handleSubmit`, skips the API call when `estimationId` is null and still calls `onComplete()`. The result page explicitly permits continuing after a save failure. | Require a saved estimation before booking; offer a save retry and only show success after the booking API confirms it. |
| High | “Marktgerechter Preis” and “Transparenter Richtpreis” accompany a price that can be changed by the customer's entered amount. `next-app/page-components/ValuationResultPage.tsx`, `applyWunschpreisCap`, caps a qualifying estimate at 92% of the entered amount and recalculates the range. For a €10,000 estimate and €8,000 entry, the displayed value becomes €7,360. | Decide whether the output represents a market estimate or a commercial offer. Align the calculation, explanation and labels. Renaming the input does not resolve this. |
| High | Confirmation says an email has been sent even when email sending fails or no Resend key is configured. `ConfirmationStep.tsx` makes an unconditional claim; `supabase/functions/book-appointment/index.ts` logs email failures but still returns booking success. | Distinguish booking saved from email sent; return delivery status and make confirmation text accurate. |
| High | Admin calendar still only offers Bodenheim and Rüsselsheim. `next-app/components/admin/CalendarTab.tsx` has a two-branch label map, state union and select options. | Add Wiesbaden to calendar creation/display and use a common branch definition. |
| Medium | Mixed address: “Deine E-Mail-Adresse” and “Deine Handynummer” in `ValuationForm.tsx`; “Ihre Preiseinschätzung” and “Wählen Sie” in results/booking. | Use formal Sie/Ihr throughout, or explicitly choose informal du across the whole customer journey. Formal Sie is already dominant. |
| Medium | The form button says “Kostenlosen Verkaufspreis erhalten”, but the result says “unverbindliche Online-Schätzung” and reserves the binding price for inspection. | Use “Kostenlose Preiseinschätzung erhalten”. “Verkaufspreis” should identify the agreed final amount. |
| Medium | Marketing and regional FAQ pages advertise free pickup, but the current public booking form only offers branch drop-off. Examples: `page-components/AutoankaufRuesselsheim.tsx` and `lib/faqContent.ts`; compare `components/BookingStep.tsx`. | Confirm whether pickup is request-only or should be selectable. State the actual process consistently. |
| Medium | Technical English can reach customers: `submit-estimation` returns “Failed to save estimation”, “Failed to update estimation”, and validation messages; result and booking pages display `error?.error` directly. | Map stable API codes to clear German messages and keep raw diagnostics in server logs. |
| Medium | “Ein Experte wird Sie innerhalb der nächsten Stunde kontaktieren” is an unconditional promise in `ConfirmationStep.tsx`, regardless of time of day. | Confirm staffed response hours; state a realistic response window and office hours. |
| Medium | “Angaben bearbeiten” in `ValuationResults.tsx` routes to `/` via `ValuationResultPage.tsx`, rather than opening the filled form for editing. | Restore the entered form data and open the appropriate step, or rename the action if it intentionally starts again. |
| Medium | “Standorte” page lists service cities but does not show the three actual branch addresses (`page-components/StandortePage.tsx`). | Separate “Unsere Filialen” with addresses from “Unsere Ankaufgebiete”. |
| Low | Awkward expressions: “Echtzeit-Geld”, “Behörden-Service” (`ValuationResults.tsx`), and “Serviceheft & HU/AU Berichte” (`ConfirmationStep.tsx`). | Prefer “Direkte Auszahlung”, “Wir übernehmen die Abmeldung”, and “Serviceheft und HU-/AU-Berichte”. Confirm whether transfer timing means initiated or received. |
| Low | Admin calendar mixes German with “Lead / Bewertung”, “Lade Leads…” and “Lead-Details öffnen” (`CalendarTab.tsx`). | Prefer “Kundenanfrage / Bewertung”, “Anfragen werden geladen…” and “Anfrage öffnen”. Conventional German terms such as Service and Checkliste are not automatically mistakes. |
| Medium | Date minimum uses `tomorrow.toISOString().split('T')[0]` in `BookingStep.tsx`; UTC conversion can produce today's local date shortly after midnight in Germany. Calendar creation uses the same pattern. | Derive the intended calendar date in the business timezone and validate it on the server. |

Suggested order: booking save correctness and email truthfulness; calendar branch consistency; pricing meaning; unified German terminology and address; marketing/service-area clarity.
